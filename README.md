Wustite is a UCI chess engine written in Rust with no external dependencies. Its built-in NNUE network was trained with [Bullet][bullet] on self-play data generated by the tools in this repository.

Library documentation is on [docs.rs](https://docs.rs/wustite).

[bullet]: https://github.com/jw1912/bullet

## Installing

Prebuilt binaries for Windows, macOS and Linux are on the [releases page](https://github.com/scriptednob/wustite/releases). You can also use one of the installers.

Linux and macOS:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/scriptednob/wustite/releases/latest/download/wustite-installer.sh | sh
```

Windows, in PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/scriptednob/wustite/releases/latest/download/wustite-installer.ps1 | iex"
```

Or with Cargo:

```sh
cargo install wustite
```

The prebuilt binaries are generic. On x86-64 they pick AVX2 at runtime. If you build for your own CPU, you get BMI2 `pext` and AVX-512BW, which run faster.

## Building from source

You need Rust 1.85 or newer. The AVX-512BW code path needs Rust 1.89 or newer.

```sh
cargo build --release
```

To build for your own CPU:

```sh
RUSTFLAGS="-C target-cpu=native" cargo build --release
```

AMD Zen 1 and Zen 2 run hardware `pext` slowly, so turn BMI2 off on those chips:

```sh
RUSTFLAGS="-C target-cpu=native -C target-feature=-bmi2" cargo build --release
```

Non-x86-64 targets, ARM included, use magic bitboards and portable scalar NNUE code.

## Usage

Wustite has no GUI. Load it into a UCI front end such as [Cute Chess](https://github.com/cutechess/cutechess), [En Croissant](https://encroissant.org), [Arena](http://www.playwitharena.de/) or [lichess-bot](https://github.com/lichess-bot-devs/lichess-bot). You can also run it straight from a terminal:

```text
wustite
uci
position startpos moves e2e4 e7e5
go movetime 1000
```

### UCI options

| Name          | Default      | Description                                                                |
| ------------- | ------------ | -------------------------------------------------------------------------- |
| Hash          | 16           | Transposition table size in MiB (1 to 65536)                               |
| Threads       | 1            | Number of Lazy SMP search threads (1 to 256)                               |
| Move Overhead | 30           | Milliseconds kept back on each move for GUI and pipe lag (0 to 5000)       |
| Ponder        | false        | Lets the GUI send `go ponder` (false or true)                              |
| UseNNUE       | true         | Use the NNUE network. When false, the PeSTO evaluation is used             |
| EvalFile      | `<internal>` | Path to a `.nnue` file, or `<internal>` for the embedded network           |
| Clear Hash    |              | Clear the transposition table                                              |

Search switches and margins can be changed with `setoption`. Integer values work as on and off, with 0 turning a switch off and any other value turning it on. For example, `setoption name NMP value 0` disables null-move pruning. The [`Params`](https://docs.rs/wustite/latest/wustite/search/struct.Params.html) and [`uci`](https://docs.rs/wustite/latest/wustite/uci/index.html) pages list them all.

### Command-line commands

| Command                        | Description                                                  |
| ------------------------------ | ------------------------------------------------------------ |
| `wustite bench [depth]`        | Run the fixed-depth [benchmark][bench] (default depth 12)    |
| `wustite perft <depth> [fen]`  | Count leaf nodes from `startpos` or a FEN, using [perft][perft] |
| `wustite divide <depth> [fen]` | Same as `perft`, with a count for each root move             |
| `wustite suite [max-depth]`    | Check the built-in perft positions (default max depth 5)     |

Inside a UCI session:

| Command            | Description                                              |
| ------------------ | -------------------------------------------------------- |
| `d`                | Print the board, FEN and Zobrist hash                    |
| `eval`             | Print the static evaluation of the position              |
| `bench [depth]`    | Run the search benchmark (default depth 10)              |
| `go perft <depth>` | Print perft counts for each root move                    |

[perft]: https://www.chessprogramming.org/Perft
[bench]: src/bench.rs

## Architecture

The board is a 64-byte aligned copy-make `Position` with incremental Zobrist hashing. Move generation is fully legal and writes into a stack-allocated `MoveList`. Sliding-piece attacks come from magic bitboards, or from BMI2 `pext` when it is enabled. All the tables are built at compile time.

Search is fail-soft PVS with iterative deepening, aspiration windows, quiescence search and Lazy SMP. It uses check and singular extensions, null-move pruning (verified at higher depths), reverse futility, futility, late move pruning, late move reductions, SEE pruning and internal iterative reduction.

Move ordering tries the transposition table move first, then captures split by SEE and sorted with MVV-LVA. After that come two killers, the counter move, butterfly history with gravity, and 1- and 2-ply continuation history.

The evaluation is an incrementally updated `(768 -> 128) x 2 -> 1` network with SCReLU activation, with AVX-512BW, AVX2 and scalar code paths. PeSTO is the fallback. In bare-king endings against a rook or a queen, a mop-up term takes over.

The transposition table is lockless and XOR-verified. It is shared across threads, in 64-byte buckets with four slots each.

## Training and tools

Self-play data comes from `examples/datagen.rs`, which writes `fen;score;wdl` lines:

```sh
cargo run --release --example datagen -- --out data.txt --threads 4 --positions 2000000 --nodes 8000
```

`--net FILE` labels positions with an existing network instead of PeSTO. The built-in network is trained from this data with Bullet. The repo also includes a pure-Rust trainer in `examples/train.rs` and a magic multiplier finder in `examples/find_magics.rs`.

Match testing and opening generation live in `tools/`. They need Python 3 and [python-chess](https://github.com/niklasf/python-chess):

```sh
python3 tools/make_openings.py target/release/wustite tools/openings.txt 200
python3 tools/match.py --bin target/release/wustite --openings tools/openings.txt --movetime 60 \
    --a "evalfile=net.nnue" --b "evalfile=nets/wustite.nnue" --games 400
```

Run the tests and build the API docs with:

```sh
cargo test --release
cargo doc --no-deps --open
```
